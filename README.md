# chat_app

同じ Wi-Fi の2台（Mac / Linux / Windows）で使う、ターミナルだけの1対1チャットとファイル送信。Python 3.8 以上の標準ライブラリだけで動く。

起動すると最初に `1) チャット  2) ファイル送受信` を選ぶ。

## はじめかた（clone から実行まで）

2台とも同じ Wi-Fi にいて、Python 3.8 以上が入っていればよい（pip でのインストールは不要）。

```
git clone https://github.com/RH-REP/chat_app.git
cd chat_app
python3 chat.py
```

1. 待つ側: `1) チャット` → `1) ホストになる`。表示された **IP と合言葉** を相手に伝える
2. つなぐ側: `1) チャット` → `2) つなぐ` → IP と合言葉を入力
3. 入力して Enter で送信、`/quit` で終了

ファイルを送るときは `2) ファイル送受信` を選び、受け取る側が `1) 受信（待機）`、送る側が `2) 送信`。1台で試すときは、ターミナルを2つ開いて `127.0.0.1` につなぐ。

### Windows の場合

- Python は python.org のインストーラーか Microsoft Store で入れる。起動は `py chat.py`（または `python chat.py`）か、`start.bat` をダブルクリック。
- 初めて待ち受けるとき（ホスト・受信）に Windows Defender ファイアウォールが許可を聞くので、**プライベート ネットワーク**で許可する。Wi-Fi の種類が「パブリック」だと外からの接続が止められるので、設定 → ネットワークとインターネット → Wi-Fi のプロパティで「プライベート」にする。
- Mac / Linux と Windows の間でもそのまま話せる。

### Mac でダブルクリックで使う（start.command）

- clone したフォルダの `start.command` をダブルクリックすると、ターミナルが開いて上のメニューが出る。受け取ったファイルは同じフォルダの `received/` に入る（`.gitignore` で除外）。
- `update.command` をダブルクリックすると、`git pull --ff-only` で最新にする。clone したフォルダのファイルを書き換えていると、取り込みを止めて知らせる。

## 使い方

```
$ python3 chat.py
1) チャット  2) ファイル送受信 > 1
1) ホストになる  2) つなぐ > 1
ホストとして待機中
  IP:     192.168.1.4
  合言葉: 4821
相手に IP と合言葉を伝えてください（止める: Ctrl+C）
```

相手の PC で:

```
$ python3 chat.py
1) チャット  2) ファイル送受信 > 1
1) ホストになる  2) つなぐ > 2
ホストの IP > 192.168.1.4
合言葉 > 4821
alice とつながりました。入力して Enter で送信、/quit で終了
```

- 1行が1件。Enter で送信、`/quit` で終了。相手が抜けると `[切断]` を出して終わる。
- 引数でも選べる: `--host`、`--join IP[:PORT]`、`--port`（既定 5050）、`--code`、`--name`（既定はログイン名）。
- 1台で試すときは、ターミナルを2つ開き、片方でホスト、もう片方で表示された IP（または `127.0.0.1`）につなぐ。

## ファイル送受信

つなぐ側からホストへの片方向。受け取る側がホスト（待機）になる。

```
（受け取る側）                                  （送る側）
$ python3 chat.py                               $ python3 chat.py
1) チャット  2) ファイル送受信 > 2              1) チャット  2) ファイル送受信 > 2
1) 受信（待機）  2) 送信 > 1                    1) 受信（待機）  2) 送信 > 2
ファイルの受け取り待ち                          ホストの IP > 192.168.1.4
  IP:     192.168.1.4                           合言葉 > 4821
  合言葉: 4821                                  送るファイル（空で終了） > ~/Desktop/report.pdf
  保存先: …/chat_app/received                   [送信中] report.pdf [#####---] 60% …
bob が report.pdf (2.4 MB) を送ろうとしています。  [完了] report.pdf → 相手の report.pdf
受け取りますか [y/N] > y                         送るファイル（空で終了） >
[保存] …/received/report.pdf（SHA-256 一致）
[終了] 1 件を受け取りました
```

- 送るファイルは1件ずつ聞かれる。Finder やエクスプローラーからターミナルへドラッグしてもよい。空行で終わる。フォルダは送れない（zip にする）。
- 引数でも: `--receive [--yes] [--save-dir DIR] [--max-size MB]`、`--send IP[:PORT] ファイル…`。
- 保存先の既定は `chat.py` の隣の `received/`（Git・複製の対象外）。同じ名前があれば `名前 (1).拡張子` にする。
- 受け取る前に確認する（`--yes` で省略）。危ない名前（`../`、`/` を含む、`.` で始まる）と Windows で使えない名前（`: * ? " < > |`、`CON`・`NUL`・`COM1` などの予約名、末尾が `.` か空白）、上限（既定 2048 MB）超え、空き容量の不足は断る。受け取る側の OS によらず同じ規則。
- 一時ファイル（`.名前.xxxx.part`）に書き、大きさと SHA-256 が合ったときだけ正式な名前にする。途中で切れたものは残さない。

## しくみ

- TCP。ホストは `0.0.0.0:5050` で待ち、最初に合言葉の合った1人とだけ話す。合わない接続は断って待ち続ける。
- 接続直後に1行ずつ名乗る: 相手 → `HELLO <合言葉> <名前>`、ホスト → `OK <名前>` か `NG <理由>`。以後は1行1件の UTF-8。
- 表示する IP は、UDP ソケットを外向きに connect して選ぶ（`gethostbyname(gethostname())` は 127.0.0.1 を返すことがある）。
- 1件の上限は 4096 文字。改行は入れられない。
- ファイル送受信は、名乗りの語を `FILES` にし、そのあとは「種類1バイト＋長さ4バイト＋中身」の枠で送る。`OFFER {name,size}` → `ACCEPT`/`REJECT` → `DATA`（64 KiB ずつ）… → `DONE {sha256}` → `SAVED`/`FAILED`、最後に `BYE`。チャットのホストにファイルの相手がつなぐと（逆も）断る。

## 制限

- **平文。**同じ Wi-Fi で通信をのぞける人には中身が見える。合言葉は、うっかりつないできた人を断るためのもの。
- 1対1。3人以上は不可。チャットしながらのファイル送信は未対応。
- ファイルの書き込みは fsync しない。受け取った直後に電源が落ちると、中身が欠けることがある。
- 相手が黙って消えた（スリープ・Wi-Fi が切れた）ときは、すぐには `[切断]` にならない。
- 受信の表示が、入力途中の行に割り込む。
- ゲスト用の SSID などで端末同士の通信が遮断されている網では使えない。
- 待機や送受信は別スレッドで動かし、主スレッドは 0.2 秒ごとに起きる。Windows では、ソケットで止まっている主スレッドに Ctrl+C が届かないため。

## テスト

```
python3 -m unittest discover -s tests
```

1台の中でホストと相手を別スレッド・別プロセスで動かす（チャット 17件、ファイル 21件）。2台の間の試験は含まない。
GitHub Actions で Linux・macOS・Windows（Python 3.12）と、Linux・Windows（Python 3.8）で回す（`.github/workflows/test.yml`）。
