# chat_app

同じ Wi-Fi の2台（Mac / Linux / Windows）で使う、1対1チャットとファイル送受信。ターミナルの版とブラウザの版があり、相手はブラウザだけでもつなげる（スマホ可）。Python 3.8 以上の標準ライブラリだけで動く。

起動すると最初のメニューで `1 チャットを待つ`・`2 チャットにつなぐ`・`3 ファイルを受け取る`・`4 ファイルを送る`・`5 ブラウザで使う` から選ぶ（Enter だけなら前回と同じもの）。

## はじめかた（clone から実行まで）

2台とも同じ Wi-Fi にいて、Python 3.8 以上が入っていればよい（pip でのインストールは不要）。

### 0. gh を入れて GitHub にログインする

GitHub の公式コマンド `gh` を入れて、ログインしておく（1台につき1回だけ）。

| OS | インストール |
|---|---|
| Mac | `brew install gh`（Homebrew が無ければ先に https://brew.sh の手順で入れる） |
| Windows | `winget install --id GitHub.cli`（入れたらターミナルを開き直す） |
| Linux | https://github.com/cli/cli#installation の手順で入れる |

```
gh auth login
```

質問には `GitHub.com` → `HTTPS` → `Yes`（Git の認証にも使う）→ `Login with a web browser` と答え、表示されたコードをブラウザに入れる。`gh auth status` で「Logged in」と出れば済み。

### 1. clone して実行する

```
git clone https://github.com/RH-REP/chat_app.git
cd chat_app
python3 chat.py
```

1. 待つ側: `1 チャットを待つ` → 合言葉に好きな4桁の数字を入れる（Enter だけならランダム）。枠に出た **IP と合言葉** を相手に伝える
2. つなぐ側: `2 チャットにつなぐ` → つなぐ欄に IP と合言葉を入れて Enter
3. 入力して Enter で送信、`/quit` で終了。`/send ファイル` でチャットのままファイルを送れる

ファイルだけを送るときは、受け取る側が `3 ファイルを受け取る`、送る側が `4 ファイルを送る`。1台で試すときは、ターミナルを2つ開いて `127.0.0.1` につなぐ。

マウスで使いたいときは `5 ブラウザで使う`（下の「ブラウザの版」）。相手が chat.py を持っていなくても、待つ側の枠に出る「ブラウザで」の住所をスマホなどのブラウザで開けば話せる（下の「相手のページ」）。

### Windows の場合

- Python は python.org のインストーラーか Microsoft Store で入れる。起動は `py chat.py`（または `python chat.py`）か、`start.bat` をダブルクリック。
- 色・状態の行・つなぐ欄は Windows 10 以降のコンソール（Windows Terminal を含む）で出る。ESC の列を有効にできない古いコンソールでは、色を付けずに1行ずつ聞く形になる。
- 初めて待つとき（チャットを待つ・ファイルを受け取る）に Windows Defender ファイアウォールが許可を聞くので、**プライベート ネットワーク**で許可する。Wi-Fi の種類が「パブリック」だと外からの接続が止められるので、設定 → ネットワークとインターネット → Wi-Fi のプロパティで「プライベート」にする。
- Mac / Linux と Windows の間でもそのまま話せる。

### Mac でダブルクリックで使う（start.command）

- clone したフォルダの `start.command` をダブルクリックすると、ターミナルが開いて上のメニューが出る。受け取ったファイルは同じフォルダの `received/` に入る（`.gitignore` で除外）。
- `update.command` をダブルクリックすると、`git pull --ff-only` で最新にする。clone したフォルダのファイルを書き換えていると、取り込みを止めて知らせる。

## 使い方

```
$ python3 chat.py
chat_app  何をしますか
  1  チャットを待つ      IP と合言葉を出して相手を待つ
  2  チャットにつなぐ    相手の IP と合言葉を入れる
  3  ファイルを受け取る  待って、届いたら保存先へ
  4  ファイルを送る      相手の IP と合言葉を入れる
  5  ブラウザで使う      このパソコンのブラウザでページを開く
番号 > 1
合言葉 [Enter でランダム] > 4821
┌───────────────────────────────────────┐
│  チャットを待っています               │
│  IP          192.168.0.9              │
│  合言葉      4 8 2 1                  │
│  ブラウザで  http://192.168.0.9:5051  │
└───────────────────────────────────────┘
相手の画面で: python3 chat.py --join 192.168.0.9 --code 4821
止める: Ctrl+C  待っています …
```

相手の PC で `2 チャットにつなぐ` を選ぶと、つなぐ欄が出る。

```
チャットにつなぐ
    相手の IP   192.168.0.9
  › 合言葉      4821
    自分の名前  bob
Tab ↑↓ 欄を移る  Enter つなぐ  Esc 戻る
```

- Tab・Shift+Tab・↑↓ で欄を移り、どの欄からでも Enter でつなぐ。Esc で最初のメニューに戻る。
- 断られたら（合言葉ちがい）合言葉の欄に、つながらなければ IP の欄に戻る。ほかの欄は残るので、打ち直すのはその欄だけ。
- 前回つないだ IP と自分の名前を `chat.py` の隣の `.chat_state.json` に覚えて、次から最初から入れておく（合言葉は覚えない。Git の対象外）。書けない場所でもそのまま動く。

つながると、一番上に状態の行、一番下に入力の行が出る。

```
 ● alice  192.168.0.9  つないで 12 分  /help  /quit
● alice とつながりました  /help でコマンド一覧
14:02 alice › 資料できた？
14:02 自分  › できた、今送る
› 明日の会議は
```

- 自分の発言は緑、相手は水色、知らせ（行頭 ●）は金茶、失敗（行頭 ✕）は赤。行頭は時刻。出力が端末でないとき・`NO_COLOR` が設定されているときは色を付けない。UTF-8 で書けない出力では罫線を `-` と `|`、印を `*`・`x`・`>` で描く。
- 打っている途中に相手の発言が届いても、打ちかけの字は入力の行に残り、発言はその上に出る。←→・Backspace・Delete・Home/End・Ctrl+U（行を消す）が使える。Ctrl+C と、空の行での Ctrl+D は `/quit` と同じ。
- 相手が新しいバージョンなら、10 秒ごとに合図を送り合う。20 秒届かないと状態の行が `◐ alice  返事が 20 秒ありません …` になり、30 秒届かないと切れたとみなして終わる。
- 待つ側の合言葉は起動のたびに聞かれる。4桁の数字を入れるとそれを使い、Enter だけならランダムな4桁にする。`--code` を付けると聞かない。
- 合言葉の間違いが 5 回たまったら、待つのをやめて終わる（チャットもファイルも）。断るたびに残りの回数を出す。4桁の数字は同じ Wi-Fi から順に試せば当たるため。
- 引数でも選べる: `--host`、`--join IP[:PORT]`、`--port`（既定 5050）、`--code`、`--name`（既定は前回の名前か、ログイン名）、`--yes`（チャットの中でも確認せずに受け取る）。
- 1台で試すときは、ターミナルを2つ開き、片方で待ち、もう片方で表示された IP（または `127.0.0.1`）につなぐ。

### チャットの中のコマンド

| コマンド | すること |
|---|---|
| `/send ファイル` | ファイルを送る。Finder やエクスプローラーからドラッグしてもよい（引用符や `\ ` で逃がした空白は外す） |
| `/open` | 保存先を開く |
| `/help` | コマンドの一覧 |
| `/quit` | 終わる |

受け取る側には次のように出て、`y` で受け取る（Enter だけなら断る）。保存先・名前の確かめ・上限・空き容量・中身の照合は、下の「ファイル送受信」と同じ決まり。

```
● alice からファイルが届きました
    名前    report.pdf
    大きさ  2.4 MB
y 受け取る  n 断る [Enter で断る] › y
受信中 report.pdf ████████████░░░░░░░░  60%  5.1 MB/s  残り 1 秒未満
✓ 保存しました  received/report.pdf  中身の照合 OK
```

相手が古いバージョンの chat.py のときは、今までどおり発言だけをやり取りする（`/send` は「相手が古いバージョンなので使えません」と出る。合図も使わない）。

## ブラウザの版

`python3 chat.py --web`（またはメニューの `5 ブラウザで使う`）で、chat.py が自分の機械の中だけ（`127.0.0.1` の空いているポート）にページを出し、既定のブラウザで開く。端末には開いた住所が出る（ブラウザが開かなければそれを開く）。

- 左のつなぐ欄に相手の IP・合言葉・自分の名前を入れて「つなぐ」。前回の IP と名前は、ターミナルの版と同じ `.chat_state.json` から入れておく。断られたら合言葉の欄に、つながらなければ IP の欄に戻る。
- 「待つ側になる」で待つ。IP と合言葉（合言葉の欄が空ならランダムな4桁）と、相手のページの住所を大きく出す。「待つのをやめる」でやめる。
- 発言の欄に自分・相手の発言と知らせ、上に状態の行（相手・つないで N 分・返事が無いときの注意・切れた）、下に入力の行（Enter で送る）。`/help`・`/send`・`/open`・`/quit` もターミナルの版と同じに使える。
- ファイルは「ファイルを選ぶ…」か、発言の欄へのドラッグで送る（いくつでも。1件ずつ順に送る）。相手が古いバージョンなら「相手が古いバージョンなので使えません」と出る。届いたファイルは、受け取りの確認（受け取る / 断る）を出し、進み具合を出して保存先へ置く。「保存先を開く」で Finder / エクスプローラーで開く。
- 相手とのやり取りはターミナルの版と同じ取り決めなので、相手はターミナルの版でもブラウザの版でもよい。
- ページを閉じると（ページとのつながりが 15 秒途切れると）chat.py も終わる。「終わる」か、端末で Ctrl+C でも終わる。
- 右上の「!」から改善のコメントを送れる（この repo の Issue。発言・名前・IP は入れない）。
- ファイル送受信のモード（メニューの 3・4）は、まだページからは使えない。ターミナルの版で使う。

## 相手のページ

チャットを待つとき（ターミナルの版でもブラウザの版でも）、待つ側は今の待ち受け（既定 5050）に加えて、同じ Wi-Fi に向けて相手のページをポート+1（既定 5051）に出す。待機の枠の「ブラウザで」の住所（例 `http://192.168.0.9:5051`）を相手に伝える。

- 相手はブラウザで開き、合言葉と名前を入れて「つなぐ」。スマホでも使える大きさ。
- 発言の送り受けのほか、「＋」でファイルを送れる（待つ側には、ほかの相手と同じ受け取りの確認が出る）。待つ側が `/send` で送ったファイルは、ページに「保存」のリンクが出て、押すとダウンロードされる。
- 待つ側から見ると、ページの相手もターミナルの相手と同じ（発言・知らせ・`/send`・`/help`・状態の行）。
- 1対1。TCP の相手とページの相手のうち、先に合言葉の合った1人とだけ話す。決まったら、もう一方の待ち受けは閉じる（2人目のブラウザには「もう相手が決まりました」）。
- 出したくないときは `--no-page`。ポート+1 が使えないときは、枠に「出せません」と出して、TCP の待ち受けだけで待つ。
- 待つ側の機械のファイアウォールが、このポートへの受信を止めていると開けない（Windows はプライベート ネットワークで許可、Mac は初回に許可を聞かれる）。

## ファイル送受信

つなぐ側から待つ側への片方向。受け取る側が待つ。チャットの中の `/send` と違い、古いバージョンの相手とも使える。

```
（受け取る側）                              （送る側）
番号 > 3                                    番号 > 4
合言葉 [Enter でランダム] > 4821            （つなぐ欄で IP と合言葉を入れる）
┌──────────────────────────────────┐        ● alice とつながりました
│  ファイルを待っています          │        送るファイル [Enter で終わる] > ~/Desktop/report.pdf
│  IP      192.168.0.9             │        ● report.pdf（2.4 MB）を申し出ました。相手の応答待ち
│  合言葉  4 8 2 1                 │        送信中 report.pdf ████████████████████ 100%  5.1 MB/s
│  保存先  …/chat_app/received     │        ✓ 送りました  report.pdf → 相手の report.pdf
└──────────────────────────────────┘        送るファイル [Enter で終わる] >
相手の画面で: python3 chat.py --send 192.168.0.9 --code 4821
● bob からファイルが届きました
    名前    report.pdf
    大きさ  2.4 MB
y 受け取る  n 断る [Enter で断る] > y
✓ 保存しました  …/received/report.pdf  中身の照合 OK
● 1 件を受け取りました
（保存先のフォルダが開く）
```

- 送るファイルは1件ずつ聞かれる。Finder やエクスプローラーからターミナルへドラッグしてもよい。空行で終わる。フォルダは送れない（zip にする）。
- 1件以上受け取って終わると、保存先のフォルダを Finder / エクスプローラー / ファイルマネージャー（`xdg-open`）で開く。開きたくないときは `--no-open`。ターミナルから使っていないとき（出力をファイルやパイプに流しているとき）は開かない。
- 引数でも: `--receive [--yes] [--no-open] [--save-dir DIR] [--max-size MB]`、`--send IP[:PORT] ファイル…`。
- 保存先の既定は `chat.py` の隣の `received/`（Git・複製の対象外）。同じ名前があれば `名前 (1).拡張子` にする。
- 受け取る前に確認する（`--yes` で省略）。危ない名前（`../`、`/` を含む、`.` で始まる）と Windows で使えない名前（`: * ? " < > |`、`CON`・`NUL`・`COM1` などの予約名、末尾が `.` か空白）、上限（既定 2048 MB）超え、空き容量の不足は断る。受け取る側の OS によらず同じ規則。
- 一時ファイル（`.名前.xxxx.part`）に書き、大きさと SHA-256 が合ったときだけ正式な名前にする（画面では「中身の照合 OK」）。途中で切れたものは残さない。

## しくみ

- TCP。待つ側は `0.0.0.0:5050` で待ち、最初に合言葉の合った1人とだけ話す。合わない接続は断って待ち続ける（合言葉の間違いは 5 回まで）。
- 接続直後に1行ずつ名乗る: つなぐ側 → `HELLO <合言葉> <名前>`（ファイルは `FILES …`）、待つ側 → `OK <名前>` か `NG <理由>`。
- 版の見分け: 新しいバージョンのつなぐ側は、チャットの名乗りの行の末尾にタブを1つ付ける。古いバージョンの待つ側は名前の前後の空白を落とすので、タブに気づかずに `OK` と答え、以後は今までどおり1行1件の UTF-8 で話す。新しいバージョンの待つ側はタブを見て `OK2 <名前>` と答え、以後は双方とも枠だけで話す。古いバージョンの待つ側に断った行やつなぎ直しを見せずに済み、往復も1回で済む。
- 枠は「種類1バイト＋長さ4バイト＋中身」。`M` 発言、`P` 合図、`B` 抜ける、ファイルは `OFFER {name,size}` → `ACCEPT`/`REJECT` → `DATA`（64 KiB ずつ）… → `DONE {sha256}` → `SAVED`/`FAILED`。新しいバージョンどうしのチャットでは、発言・合図・ファイルを同じつながりで混ぜ、どちらの向きにも送れる。知らない種類の枠は読み捨てる。
- ファイル送受信のつながり（`FILES`）は、名乗りのあと今までどおりの枠で片方向に送る。チャットの待つ側にファイルの相手がつなぐと（逆も）断る。
- 表示する IP は、UDP ソケットを外向きに connect して選ぶ（`gethostbyname(gethostname())` は 127.0.0.1 を返すことがある）。
- 1件の上限は 4096 文字。改行は入れられない。相手の発言に入った制御文字（ESC など）は `?` にして出す。
- 通信と取り決めは `chat.py`（`ChatSession` が受信・合図・ファイルを受け持ち、表示は渡されたものに任せる）、ターミナルの画面と入力は `chat_term.py`、ブラウザの版と相手のページは `chat_web.py` と `web/`。
- ブラウザの版: `http.server`（`ThreadingHTTPServer`）を `127.0.0.1` の空いているポートに出す。起動ごとに `secrets` で鍵を作って URL（`?k=`）に入れ、ページはそれを頭書き（`X-Chat-Key`）と cookie（`HttpOnly`・`SameSite=Strict`、ポートごとの名前）で返す。鍵の無い要求、`Host` が `127.0.0.1:ポート` / `localhost:ポート` でない要求（DNS rebinding）、`Origin` の無い・ちがう書き込み、`Sec-Fetch-Site` が別のサイトの要求は 403。ページ → 手元は `fetch`、ファイルは `XMLHttpRequest`（`upload.onprogress` で進み具合）で中身を手元へ送り（ブラウザは元の場所を教えないため）、一時フォルダを経て `ChatSession` の `/send` と同じ道で相手へ送る。手元 → ページは Server-Sent Events。出来事には番号を付けてためておき、ページを読み直すと続きから流し直す。`ChatSession` に渡す表示を `WebView`（出来事にする）に差し替えるだけで、通信の核は同じ。
- 相手のページ: 待つ側の `ChatSession` からは、ページの相手を `PagePeer`（`FramedPeer` と同じ口）として扱う。ページの発言・合図（5 秒ごと）・抜ける・ファイルを枠に直して渡し、待つ側の枠をページの出来事に直す。待つ側から送るファイルは一時フォルダで受けて大きさと SHA-256 を照合し、ページに `Content-Disposition: attachment` のリンクを出す。合言葉の間違いの回数と「最初の1人」は TCP とページで1つの札（`WaitGate`）を分け合う。数えるのは合言葉を送ってきた要求だけ（`/favicon.ico` などは数えない）。合ったブラウザに鍵の cookie（`HttpOnly`・`SameSite=Strict`）を渡し、以後は鍵の無い要求を断る。書き込みは `Origin` が `Host` と同じものだけ受ける。相手が何も送らずに切った接続（スマホのブラウザの先回りの接続）でトレースバックを出さないよう、`handle_error` で `ConnectionError`・`TimeoutError` を黙って捨てる。
- 入力の行はキーを1つずつ読む自前の入力（Mac/Linux は `termios`、Windows は `msvcrt.getwch`）。`readline` は OS や Python によって中身が違うので使わない。状態の行は ESC の列のスクロール範囲（`ESC [2;N r`）で1行目を残す。ウインドウの大きさが変わったら、Mac/Linux は `SIGWINCH`、Windows は 0.5 秒ごとに大きさを見て描き直す。終わるとき（例外でも）は端末の設定とスクロール範囲を戻す。
- 入力も出力も端末でないとき（パイプ・テスト）は、メニュー・IP・合言葉を1行ずつ聞き、発言も1行ずつ読む形になる。

## 制限

- **平文。**同じ Wi-Fi で通信をのぞける人には中身が見える。合言葉は、うっかりつないできた人を断るためのもの。相手のページも http のままで、合言葉・鍵の cookie・発言・ファイルはのぞき見を防がない。
- 相手のページのブラウザが裏に回る・スマホが眠ると合図（5 秒ごと）が止まり、30 秒でつながりが切れたとみなす（ターミナルの相手と同じ）。つなぎ直すには待つ側がもう一度待つ。
- ブラウザの版のページは、ブラウザがタブを強く眠らせると（長く裏に置くなど）ページとのつながりが切れて、15 秒で chat.py が終わることがある。
- 同じ Mac で動くほかのプログラムは、鍵を知らなくても `127.0.0.1` に要求は送れる（鍵が無いので断る）。鍵は端末とブラウザの履歴に残る。
- 1対1。3人以上は不可。
- ファイルの書き込みは fsync しない。受け取った直後に電源が落ちると、中身が欠けることがある。
- 相手が古いバージョンのときは、相手が黙って消えた（スリープ・Wi-Fi が切れた）ことにすぐには気づかない。チャットの中の `/send` も使えない。
- 日本語の入力（IME）で確定した字は受け取れるはずだが、3つの OS の実機では試していない。「●」などの幅があいまいな字を2字分で描く端末では、状態の行の右端が1字ずれることがある。
- 1行に収まらない発言は端末が折り返す。入力の行は横に送って見せる。
- ゲスト用の SSID などで端末同士の通信が遮断されている網では使えない。
- 待機や送受信は別スレッドで動かし、主スレッドは 0.2 秒ごとに起きる。Windows では、ソケットで止まっている主スレッドに Ctrl+C が届かないため。
